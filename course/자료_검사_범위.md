# 개정14 화면 참고판 — 이번 검사의 범위

## 바뀐 것
공식 Unity 문서에서 원본 픽셀을 열어 확인한 UI 캡처 **8종**과 별도 한국어 읽기 안내를 연결했습니다. **139개 관련 실습에 152개 연결**이 있습니다. 같은 사진을 여러 문맥에 연결한 수이며, 139장의 서로 다른 사진을 찍었다는 뜻이 아닙니다. 관련 없는 하네스 단계에 무관한 Editor 이미지를 강제로 넣지 않았습니다.

Editor 전체 배치(2022.3), Console(문서6.3), Sprite Editor 선택 영역(문서6.3), Input Actions(패키지1.17), Animator(문서6.3의 이전 UI 예시), UI Builder(문서6.3의 preview UI 예시), Profiler(문서6.0), Project 창의 Build Profile 자산(문서6.3)을 제공합니다. 문서 버전은 캡처 빌드의 보증이 아닙니다. 모든 화면에 버전 차이와 읽을 위치를 표시했습니다.

## 이미지 보관·네트워크
**공식 이미지 파일은 로컬 다운로드에 성공하지 못했고 HTML/ZIP에 이미지 바이트를 넣지 않았습니다.** 컨테이너의 외부 네트워크 DNS 접근이 불가했습니다. 원본 URL은 웹 도구로 열어 실제 UI를 직접 확인했습니다. HTML은 사용자가 버튼을 눌렀을 때 공식 서버의 원본을 요청합니다. 시작·실습 변경·참고 설명 펼치기만으로 이미지를 요청하지 않습니다. 따라서 이미지 열기에는 인터넷과 공식 서버 접근이 필요합니다. 실패하면 알림·재시도·공식 원문 링크를 제공하며 가짜 화면으로 대체하지 않습니다.

## 실제 실행한 검사
- **68개 구조·UI 판정 통과.** 기존 10개 JSON 데이터 블록의 정확한 보존, 256개 원래 실습의 참고 패널 연결 여부, 8종의 출처·버전·관련 실습·추가 요청, 검색, 복사 원문, 네트워크 실패, 확대·닫기·원본 크기, 진행 상태 보존, 1440/390px 라이트·다크 가로 넘침 등을 확인했습니다. 256개 렌더 대조는 이 중 한 묶음이며 독립 게임 테스트 수가 아닙니다.
- 브라우저는 시스템 Chromium을 사용하고 HTML 바이트를 set_content로 주입했습니다. 사용자 Windows에서 파일을 더블클릭해 여는 경로·원본 사이트의 임베딩 허용·모든 브라우저의 지속 저장을 검증한 것은 아닙니다.
- **이미지 성공 처리·확대 동작에는 1×1 시험용 픽셀을 응답하는 네트워크 모형을 사용했습니다.** 이 검사는 onload 처리만 검사합니다. 실제 공식 스크린샷의 로컬 브라우저 디코딩·해상도·전송 성공을 검사했다고 주장하지 않습니다. 시험 픽셀은 학생용 HTML과 참고 화면에 포함하지 않았습니다.
- 실패 처리는 실제 브라우저 요청을 테스트 코드에서 차단해 확인했습니다. 화면 예시는 이미지가 아직 로드되지 않은 한국어 안내 상태에서만 저장했습니다.
- 최종 ZIP을 다시 열어 파일별 해시를 대조했습니다. 하네스·스킬·게임 요청의 원문을 이 추가 작업에서 변경하지 않았습니다. 해당 실행 코드의 전체 단위 테스트는 이번에 다시 실행하지 않았습니다.

## 검사 과정에서 고친 것
Playwright의 기본 다운로드 브라우저가 없어 이미 설치된 시스템 Chromium 경로를 사용했습니다. 검색 범위에서 ‘퀘스트’가 질문에만 있어 UI Builder를 찾지 못하던 문제를 고쳤습니다. 퀘스트 편집기 관련 실습은 Console보다 UI Builder를 먼저 표시하도록 정리했습니다. 검색 결과가 언제나 하나라는 초기 검사 가정은 실제로 필요한 화면이 포함되는지 확인하는 조건으로 바로잡았습니다.

## 미실행과 범위 구분
실제 Unity Editor·C# 컴파일·프로젝트 캡처·게임 빌드·AI 도구 연결·휴대폰 조작·Profiler 측정은 수행하지 않았습니다. 특히 과정의 맞춤 퀘스트 편집기와 게임은 공식 예시 화면과 다릅니다. 독립 서브에이전트 심사나 수강생 완주 검사도 수행하지 않았습니다. 기존 v13의 검토 후보 상태는 유지됩니다.
