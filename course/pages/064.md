# 064. 추가 결제 없이 AI로 2D 프레임 만들기

**목표:** 단순한 그림을 직접 쓸 수 있는 동작으로 만듭니다.

**시작 상태:** 기본 아트와 로컬 파일 생성 도구

## 한눈에 보는 기능의 흐름

단순 그림 → 부위·포즈 구성 → 프레임·루프 → 게임에 연결

![추가 결제 없이 AI로 2D 프레임 만들기 — 개념 설명용 구조](../lesson_visuals/064.svg)

**경계:** 그림 애니메이션이 몸체를 따로 옮기지 않기

그림은 실제 게임 실행 결과가 아닙니다. 값·규칙과 예제를 필요한 때 펼쳐 읽고 현재 단계의 메시지를 한 번씩 보냅니다.

## 1. 지금 상태 확인하기

첫 메시지를 보내 현재 준비 상태를 확인합니다. AI가 읽어 온 실제 프로젝트가 맞는지 보고, 없는 준비나 다른 상태가 있으면 먼저 알려 주세요. 아직 기능을 만들지 않는 단계입니다.

### AI에게 보낼 요구와 이유

#### 01. 작업 대상부터 확인

**“추가 결제 없이 AI로 2D 프레임 만들기” 작업을 시작하기 전에 현재 상태를 읽기 전용으로 확인해 줘.**

왜 이렇게 요청하나요? AI가 다른 프로젝트나 오래된 예제를 보고 작업할 수 있습니다. 실제 경로·파일·현재 기능을 읽게 하면 지금 이어서 작업할 대상을 먼저 맞출 수 있습니다.

#### 02. 작업 대상부터 확인

**필요한 시작 상태는 기본 아트와 로컬 파일 생성 도구야.**

왜 이렇게 요청하나요? AI가 다른 프로젝트나 오래된 예제를 보고 작업할 수 있습니다. 실제 경로·파일·현재 기능을 읽게 하면 지금 이어서 작업할 대상을 먼저 맞출 수 있습니다.

#### 03. 실제 사용 중인 구현 재사용

**실제 프로젝트와 작업 기록을 읽고 이것이 준비되어 있는지, 이미 같은 기능이 있는지 확인해 줘.**

왜 이렇게 요청하나요? 이름이 비슷한 새 클래스를 또 만들면 기존 화면은 여전히 옛 코드를 사용할 수 있습니다. 실제 호출되는 진입점을 찾아 연결해야 두 구현이 충돌하거나 수정이 반영되지 않는 문제를 막습니다.

#### 04. 현재 상태와 다음 확인 지점 구분

**이번 기능이 연결될 실제 파일·화면·도구와 보존할 기존 동작을 짧게 정리해 줘.**

왜 이렇게 요청하나요? 이미 준비된 기능과 아직 확인하지 못한 기능을 섞으면 불필요한 재설치나 성급한 완료 판정이 생깁니다. 현재 대상과 남은 준비를 나눠 가장 작은 다음 작업을 선택하게 합니다.

#### 05. 조사 단계에서 변경하지 않기

**아직 새 구현·설치·유료 호출·파일 변경은 하지 마.**

왜 이렇게 요청하나요? 현재 상태를 알아보기만 할 때 파일 변경이나 결제가 시작되면 검토 전의 환경이 바뀝니다. 준비 확인과 실제 구현을 나눠 되돌리기 어려운 작업이 먼저 실행되지 않게 합니다.

#### 06. 막힌 준비를 먼저 해결

**준비가 다르면 부족한 항목과 다음에 필요한 작업을 알려 줘.**

왜 이렇게 요청하나요? 빠진 파일·권한·패키지를 있다고 가정하면 다음 구현이 엉뚱한 대상을 만들게 됩니다. 무엇이 없고 무엇을 먼저 해야 하는지 분리하면 불필요한 재작업을 줄일 수 있습니다.

## 2. 필요한 기능 만들기

준비가 확인되면 아래 요청을 보냅니다. AI가 파일·설정·실행을 맡습니다. 변경 범위나 비용 승인이 나오면 내용을 읽고 결정하세요.

### AI에게 보낼 요구와 이유

#### 01. 작업 대상부터 확인

**현재 프로젝트의 실제 파일과 이미 결정한 규칙을 먼저 확인해 줘.**

왜 이렇게 요청하나요? AI가 다른 프로젝트나 오래된 예제를 보고 작업할 수 있습니다. 실제 경로·파일·현재 기능을 읽게 하면 지금 이어서 작업할 대상을 먼저 맞출 수 있습니다.

#### 02. 실제 사용 중인 코드에 연결

**이름이 다른 기존 구현이 있으면 새로 중복 제작하지 말고 그 구현에 연결해 줘.**

왜 이렇게 요청하나요? 예제와 이름이 다르더라도 현재 씬과 입력에서 호출하는 구현이 작업 대상입니다. 같은 기능을 새로 만들기보다 기존 진입점을 확인해 수정이 실제 게임에 반영되고 중복 실행되지 않게 합니다.

#### 03. 프레임의 순서와 시간 맞추기

**추가 이미지 생성 서비스에 결제하지 않고 기본 캐릭터 프레임을 직접 생성·편집하는 도구를 네가 만들어 실행해 줘.**

왜 이렇게 요청하나요? 이미지나 동작 파일이 있어도 순서·속도·전환 기준이 맞지 않으면 끊기거나 타격 시점과 어긋납니다. 실제 사용 크기와 반복 재생에서 연결이 자연스러운지 확인합니다.

#### 04. 알파·RGBA·투명 배경의 적용 조건

**현재 승인된 기본 그림이 없으면 단순한 도형으로 회색 갑옷·청록색 망토·검의 모험가를 실제 PNG로 만들어 줘.**

왜 이렇게 요청하나요? RGBA는 빨강·초록·파랑의 색 채널과 투명도를 나타내는 알파 채널입니다. 흰 배경이나 체크무늬가 그려진 이미지가 실제 투명 이미지인 것은 아닙니다. 알파 0인 픽셀의 색값과 필터링이 가장자리 후광에 영향을 줄 수 있습니다. 한 배경에서만 검사하지 않습니다.

#### 05. 그림 크기와 월드 크기 연결

**64×64 RGBA 고정 캔버스와 발 (32,56)을 유지하며 남쪽 걷기 6프레임, 공격 준비·타격·회수 6프레임을 만들어 줘.**

왜 이렇게 요청하나요? 픽셀 수만 정하면 게임 안에서의 크기는 정해지지 않습니다. PPU와 배율을 함께 고정해야 자산을 바꿔도 캐릭터·바닥·UI의 크기 관계를 비교할 수 있습니다.

#### 06. 프레임의 순서와 시간 맞추기

**팔·검·몸을 분리한 부위 애니메이션 후보도 작은 사본에서 비교해 줘.**

왜 이렇게 요청하나요? 이미지나 동작 파일이 있어도 순서·속도·전환 기준이 맞지 않으면 끊기거나 타격 시점과 어긋납니다. 실제 사용 크기와 반복 재생에서 연결이 자연스러운지 확인합니다.

#### 07. 프레임의 기준점 통일

**파일 편집·피벗·키프레임·패킹·Unity 설정은 직접 맡아 줘.**

왜 이렇게 요청하나요? 걷기·공격 그림의 몸통 크기가 달라도 발은 같은 위치에 있어야 합니다. 기준점이 다르면 몸체는 정지해 있는데 그림만 튀거나 바닥을 미끄러지는 것처럼 보입니다.

#### 08. 구현할 결과와 조건 고정

**AI 도구 자체의 사용료와 추가 이미지 서비스 비용 없음은 구분해 줘.**

왜 이렇게 요청하나요? “AI 도구 자체의 사용료와 추가 이미지 서비스 비용 없음은 구분해 줘”를 명시하면 AI가 무엇을 구현하거나 검사해야 하는지 범위를 좁힐 수 있습니다. 단순한 그림을 직접 쓸 수 있는 동작으로 만듭니다. 이 결과를 확인할 때 이 조건이 실제로 반영됐는지 함께 봅니다.

#### 09. 프레임의 순서와 시간 맞추기

**ArtLab2D에서 프레임 방식과 부위 방식의 실제 재생을 보여 줘.**

왜 이렇게 요청하나요? 이미지나 동작 파일이 있어도 순서·속도·전환 기준이 맞지 않으면 끊기거나 타격 시점과 어긋납니다. 실제 사용 크기와 반복 재생에서 연결이 자연스러운지 확인합니다.

#### 10. 관찰 가능한 기준으로 확인

**발 미끄러짐·몸체 크기·검 손·팔 연결을 확인하고 내가 선택한 한 방식을 채택해 줘.**

왜 이렇게 요청하나요? 구현 완료라는 설명을 실제 결과로 바꾸기 위한 조건입니다. 요청에 나온 대상과 경계 상황을 확인해 정상 결과뿐 아니라 실패를 어떻게 구분했는지도 남깁니다.

#### 11. 구현할 결과와 조건 고정

**기존 몸체·피해 타이밍은 바꾸지 마.**

왜 이렇게 요청하나요? “기존 몸체·피해 타이밍은 바꾸지 마”를 명시하면 AI가 무엇을 구현하거나 검사해야 하는지 범위를 좁힐 수 있습니다. 단순한 그림을 직접 쓸 수 있는 동작으로 만듭니다. 이 결과를 확인할 때 이 조건이 실제로 반영됐는지 함께 봅니다.

#### 12. 구현과 실행은 AI에게 맡기기

**코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘.**

왜 이렇게 요청하나요? 설명이나 코드 조각만 받으면 실제 파일 생성·연결·실행이 빠질 수 있습니다. AI가 개발 작업까지 수행하고, 사람은 요구·승인·결과 판단을 맡도록 역할을 분명히 합니다.

#### 13. 막힌 준비를 먼저 해결

**수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.**

왜 이렇게 요청하나요? 빠진 파일·권한·패키지를 있다고 가정하면 다음 구현이 엉뚱한 대상을 만들게 됩니다. 무엇이 없고 무엇을 먼저 해야 하는지 분리하면 불필요한 재작업을 줄일 수 있습니다.

## 3. 결과를 직접 확인하기

먼저 확인 요청을 보내 AI가 검사와 화면을 준비하게 하세요. 그다음 아래 동작을 하나씩 확인합니다.

### AI에게 보낼 요구와 이유

#### 01. 검사할 입력과 관찰 지점 준비

**방금 구현한 기능의 자동 검사와 확인 화면을 준비해 줘.**

왜 이렇게 요청하나요? 정상 예 하나만 보면 실패 조건을 놓치기 쉽습니다. 정상·경계·반례를 실제 입력으로 준비하고 사람이 볼 화면도 맞춰 확인 범위를 분명하게 합니다.

#### 02. 결과를 재확인할 근거 남기기

## 왜 이렇게 만드는가

**서비스 확인 범위:** 아래 서비스별 기능·가격 예시는 아래 조사 자료다. 이번 개정의 실습 변경과 최신 요금 확인은 별개이며, AI는 실제 호출 전에 공식 지원·계정·단가·자동화 경로를 다시 확인한다. 비용 승인은 현재 확인한 값으로 받는다.
