# 069. 베기와 폭발을 시트 애니메이션으로 만들기

**목표:** 프레임 효과가 타격 시점에 맞게 재생됩니다.

**시작 상태:** 실제 효과용 이미지 또는 생성 경로

## 한눈에 보는 기능의 흐름

효과 시트 → 프레임 순서 → 재생 속도 → 공격 사건 연결

## 1. 지금 상태 확인하기

첫 메시지를 보내 현재 준비 상태를 확인합니다. AI가 읽어 온 실제 프로젝트가 맞는지 보고, 없는 준비나 다른 상태가 있으면 먼저 알려 주세요. 아직 기능을 만들지 않는 단계입니다.

### AI에게 보낼 요구와 이유

#### 01. 작업 대상부터 확인

**“베기와 폭발을 시트 애니메이션으로 만들기” 작업을 시작하기 전에 현재 상태를 읽기 전용으로 확인해 줘.**

왜 이렇게 요청하나요? AI가 다른 프로젝트나 오래된 예제를 보고 작업할 수 있습니다. 실제 경로·파일·현재 기능을 읽게 하면 지금 이어서 작업할 대상을 먼저 맞출 수 있습니다.

#### 02. 작업 대상부터 확인

**필요한 시작 상태는 실제 효과용 이미지 또는 생성 경로야.**

왜 이렇게 요청하나요? AI가 다른 프로젝트나 오래된 예제를 보고 작업할 수 있습니다. 실제 경로·파일·현재 기능을 읽게 하면 지금 이어서 작업할 대상을 먼저 맞출 수 있습니다.

#### 03. 실제 사용 중인 구현 재사용

**실제 프로젝트와 작업 기록을 읽고 이것이 준비되어 있는지, 이미 같은 기능이 있는지 확인해 줘.**

왜 이렇게 요청하나요? 이름이 비슷한 새 클래스를 또 만들면 기존 화면은 여전히 옛 코드를 사용할 수 있습니다. 실제 호출되는 진입점을 찾아 연결해야 두 구현이 충돌하거나 수정이 반영되지 않는 문제를 막습니다.

#### 04. 현재 상태와 다음 확인 지점 구분

**이번 기능이 연결될 실제 파일·화면·도구와 보존할 기존 동작을 짧게 정리해 줘.**

왜 이렇게 요청하나요? 이미 준비된 기능과 아직 확인하지 못한 기능을 섞으면 불필요한 재설치나 성급한 완료 판정이 생깁니다. 현재 대상과 남은 준비를 나눠 가장 작은 다음 작업을 선택하게 합니다.

#### 05. 조사 단계에서 변경하지 않기

**아직 새 구현·설치·유료 호출·파일 변경은 하지 마.**

왜 이렇게 요청하나요? 현재 상태를 알아보기만 할 때 파일 변경이나 결제가 시작되면 검토 전의 환경이 바뀝니다. 준비 확인과 실제 구현을 나눠 되돌리기 어려운 작업이 먼저 실행되지 않게 합니다.

#### 06. 막힌 준비를 먼저 해결

**준비가 다르면 부족한 항목과 다음에 필요한 작업을 알려 줘.**

왜 이렇게 요청하나요? 빠진 파일·권한·패키지를 있다고 가정하면 다음 구현이 엉뚱한 대상을 만들게 됩니다. 무엇이 없고 무엇을 먼저 해야 하는지 분리하면 불필요한 재작업을 줄일 수 있습니다.

## 2. 필요한 기능 만들기

준비가 확인되면 아래 요청을 보냅니다. AI가 파일·설정·실행을 맡습니다. 변경 범위나 비용 승인이 나오면 내용을 읽고 결정하세요.

### AI에게 보낼 요구와 이유

#### 01. 작업 대상부터 확인

**현재 프로젝트의 실제 파일과 이미 결정한 규칙을 먼저 확인해 줘.**

왜 이렇게 요청하나요? AI가 다른 프로젝트나 오래된 예제를 보고 작업할 수 있습니다. 실제 경로·파일·현재 기능을 읽게 하면 지금 이어서 작업할 대상을 먼저 맞출 수 있습니다.

#### 02. 실제 사용 중인 코드에 연결

**이름이 다른 기존 구현이 있으면 새로 중복 제작하지 말고 그 구현에 연결해 줘.**

왜 이렇게 요청하나요? 예제와 이름이 다르더라도 현재 씬과 입력에서 호출하는 구현이 작업 대상입니다. 같은 기능을 새로 만들기보다 기존 진입점을 확인해 수정이 실제 게임에 반영되고 중복 실행되지 않게 합니다.

#### 03. 프레임 배열과 재생 규격 맞추기

**스프라이트 시트로 베기 궤적·마법 폭발 효과를 만들어 줘.**

왜 이렇게 요청하나요? 한 장에 그림이 여러 개 있어도 셀 크기·순서·여백이 일정하지 않으면 잘못 잘라 재생됩니다. 원본과 잘린 프레임을 대조해야 잘림·순서 뒤집힘·위치 튐을 찾을 수 있습니다.

#### 04. 비용과 외부 작업은 별도 승인

**승인된 실제 시트를 쓰거나 도형 프레임을 네가 생성하고, 없는 외부 아트를 있다고 가정하지 마.**

왜 이렇게 요청하나요? 로컬 파일을 고치는 것과 외부 서비스에 자료를 보내거나 비용을 지불하는 것은 영향이 다릅니다. 대상·내용·비용 범위를 확인한 승인 없이 요청이 확대되지 않도록 합니다.

#### 05. 실제 투명 데이터 확인

**프레임 수·순서·알파·반복 여부를 명시하고 Particle System의 시트 애니메이션이나 단순 플립북 중 현재 프로젝트에 맞는 한 경로를 선택해 줘.**

왜 이렇게 요청하나요? 바둑판이 그려진 이미지와 배경 픽셀의 알파가 투명한 파일은 다릅니다. 배경 위에 겹쳐 확인해야 사각 테두리나 번짐이 게임에 그대로 나타나는 것을 막습니다.

#### 06. 구현할 결과와 조건 고정

**베기 궤적은 공격 방향을, 폭발은 효과 중심을 따르게 해 줘.**

왜 이렇게 요청하나요? “베기 궤적은 공격 방향을, 폭발은 효과 중심을 따르게 해 줘”를 명시하면 AI가 무엇을 구현하거나 검사해야 하는지 범위를 좁힐 수 있습니다. 프레임 효과가 타격 시점에 맞게 재생됩니다. 이 결과를 확인할 때 이 조건이 실제로 반영됐는지 함께 봅니다.

#### 07. 프레임의 순서와 시간 맞추기

**실제 피해 타이머와 범위는 전투 데이터가 소유하고 효과 재생 완료 이벤트가 피해를 또 발생시키지 않게 해 줘.**

왜 이렇게 요청하나요? 이미지나 동작 파일이 있어도 순서·속도·전환 기준이 맞지 않으면 끊기거나 타격 시점과 어긋납니다. 실제 사용 크기와 반복 재생에서 연결이 자연스러운지 확인합니다.

#### 08. 프레임의 순서와 시간 맞추기

**풀 재사용·중간 취소·씬 종료·낮은 프레임에서 마지막 프레임이나 이전 효과가 남지 않는지 확인해 줘.**

왜 이렇게 요청하나요? 이미지나 동작 파일이 있어도 순서·속도·전환 기준이 맞지 않으면 끊기거나 타격 시점과 어긋납니다. 실제 사용 크기와 반복 재생에서 연결이 자연스러운지 확인합니다.

#### 09. 피할 수 있는 정보와 실제 판정 일치

**예고 원과 실제 피해 반경을 함께 보여 줘.**

왜 이렇게 요청하나요? 표시한 위험 범위·시점과 실제 피해가 다르면 플레이어는 올바르게 반응해도 손해를 봅니다. 예고·판정·효과가 같은 규칙을 사용하게 해 공격을 학습할 수 있게 합니다.

#### 10. 구현과 실행은 AI에게 맡기기

**코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘.**

왜 이렇게 요청하나요? 설명이나 코드 조각만 받으면 실제 파일 생성·연결·실행이 빠질 수 있습니다. AI가 개발 작업까지 수행하고, 사람은 요구·승인·결과 판단을 맡도록 역할을 분명히 합니다.

#### 11. 막힌 준비를 먼저 해결

**수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.**

왜 이렇게 요청하나요? 빠진 파일·권한·패키지를 있다고 가정하면 다음 구현이 엉뚱한 대상을 만들게 됩니다. 무엇이 없고 무엇을 먼저 해야 하는지 분리하면 불필요한 재작업을 줄일 수 있습니다.

## 3. 결과를 직접 확인하기

먼저 확인 요청을 보내 AI가 검사와 화면을 준비하게 하세요. 그다음 아래 동작을 하나씩 확인합니다.

### AI에게 보낼 요구와 이유

#### 01. 검사할 입력과 관찰 지점 준비

**방금 구현한 기능의 자동 검사와 확인 화면을 준비해 줘.**

왜 이렇게 요청하나요? 정상 예 하나만 보면 실패 조건을 놓치기 쉽습니다. 정상·경계·반례를 실제 입력으로 준비하고 사람이 볼 화면도 맞춰 확인 범위를 분명하게 합니다.

#### 02. 결과를 재확인할 근거 남기기

**정상 동작과 아래 실패 조건을 실제로 검사하고 대상·실행 수·결과를 보여 줘.**

왜 이렇게 요청하나요? “잘 됩니다”라는 요약만으로는 어떤 입력과 버전을 검사했는지 알 수 없습니다. 대상·실행 수·실패 내용·파일을 함께 남겨 같은 조건으로 다시 확인할 수 있게 합니다.

#### 03. 프레임의 순서와 시간 맞추기

**자동 검사: 프레임 수16, 범위를 벗어난 UV 없음,1회 종료 후 반환이다.**

왜 이렇게 요청하나요? 이미지나 동작 파일이 있어도 순서·속도·전환 기준이 맞지 않으면 끊기거나 타격 시점과 어긋납니다. 실제 사용 크기와 반복 재생에서 연결이 자연스러운지 확인합니다.

#### 04. 효과를 표현 계층에 연결

## 왜 이렇게 만드는가

캐릭터 시트는 인물의 동일성을 유지해야 하고, 효과 시트는 에너지가 생기고 사라지는 흐름이 중요하다. 폭발은 시작·팽창·잔광을, 베기는 짧은 궤적을 읽을 수 있어야 한다. 효과 이미지의 큰 불꽃이 실제 피해 반경을 오해하게 만들지 않도록 한다.

Unity Particle System의 Texture Sheet Animation은 격자 텍스처를 프레임으로 재생하거나 Sprite 목록으로 재생할 수 있다. Grid/Sprites 방식, 행/열과 FPS 또는 수명 기반 재생을 현재 모듈에서 확인한다. [N20]
