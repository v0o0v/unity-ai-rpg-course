내가 만든 하네스의 실제 경로와 현재 게임 후보를 확인하고 game-feature로 이 작업을 처리해 줘. 필요한 담당 역할만 고르고 구현·QA·독립 검토를 분리해 줘. 변경안·승인한 후보·Unity 통합·현재 소스 검사를 실제로 연결하고, 참고 완성본으로 우회하지 마.

schema3 통합 저장과 schema2 이전·손상 복구를 완성해 줘.
영구 필드와 run/UI 임시 상태를 명시적으로 분리해 줘.
정상 옛 저장의 ID·옵션·진행을 보존하고 미래 버전을 조용히 덮어쓰지 마.
중복 ID·음수/한도초과 재료·호환 불가 룬을 검증하고 유효한 백업만 복원해 줘.
거래 저장 전후 종료를 사본에서 주입하고 request영수증·revision과 아이템/재료가 같이 복원되는지 검사해 줘.
실제 Android 내구 검사 미실행은 NOT RUN으로 남겨 줘.

이 기능의 규칙:
영구 상태는 materialWallet·runeWallet·stash·favoriteIds·socketData·skillVariants·forgeQuest·droneUnlocked·codex를 저장한다. 유물·전투 상태·바닥 드롭·동료 위치·열린 UI는 저장하지 않는다. 기존 장비 ID·옵션·레벨·퀘스트·스킬트리는 보존한다.

schema2→3 변환은 명시적 기본값을 넣고 원본 백업을 유지한다. 미래 버전 저장을 오래된 앱이 읽으면 알 수 없는 필드를 버린 채 다시 저장하지 말고 안전하게 중단한다. 파일 파싱이 성공했다고 전체 소유 ID·수량 한도·룬 호환성까지 유효한 것은 아니므로 검증 단계를 둔다.

마을 거래의 저장 커밋은 잔액·아이템·revision·request 영수증을 같은 상태에 포함한다. 이전 영수증은 정한 보존 창까지 유지한다. 저장 완료와 UI 표시 사이에 앱이 종료되어도 재시작 후 동일 request의 결과를 확인할 수 있어야 한다. 사용자에게 내구 저장을 약속하려면 실제 Android 저장·강제 종료 상황에서 확인해야 한다. 아래 파일 교체 설계는 기기별 내구성 보장을 대신하지 않는다.

코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘. 수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.
