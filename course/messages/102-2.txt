현재 프로젝트의 실제 파일과 이미 결정한 규칙을 먼저 확인해 줘. 이름이 다른 기존 구현이 있으면 새로 중복 제작하지 말고 그 구현에 연결해 줘.

3D Windows 와 Android 배포물을 만들어 줘.
기존 2D 결과물과 앱 ID·저장·콘텐츠 경로를 덮어쓰지 마.
3D 부트 씬·Universal Renderer·LocalCore·Addressables Profile을 확인한 뒤 별도 폴더에 빌드해 줘.
Windows 는 Editor 없이 실행, Android 는 실제 APK 설치로 검증해 줘.
AAB/스토어 제출은 별도 선택 단계이며 서명 키나 비밀번호를 기록하지 마.
네 조합의 산출물 경로·해시·빌드 설정·실제 실행 여부를 표로 남겨 줘.

적용할 세부 규칙:
배포 폴더 예시는 Builds/2D/Windows, Builds/2D/Android, Builds/3D/Windows, Builds/3D/Android 다. Android 앱 ID는 본인의 도메인 규칙으로2d/3d를 구분한다. 기존 앱 업데이트 정책이 필요한 실서비스는 작업 예시와 별도로 검토한다.

테스트은 APK 설치를 우선하고, AAB는 선택 스토어 준비물로 다룬다. AAB를 APK처럼 바로 설치하는 절차를 안내하지 않는다. 서명 키·비밀번호는 저장소나 프로젝트 문서에 넣지 않는다.

3D의 부트 씬과 Renderer, LocalCore, 원격 Profile이 들어가는지 확인하고 개발용 2D 테스트 씬·Debug UI가 배포물에 잘못 포함되지 않는지 검사한다.

코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘. 수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.
