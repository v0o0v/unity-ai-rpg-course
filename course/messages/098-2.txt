현재 프로젝트의 실제 파일과 이미 결정한 규칙을 먼저 확인해 줘. 이름이 다른 기존 구현이 있으면 새로 중복 제작하지 말고 그 구현에 연결해 줘.

3D Addressables 팩을 구성해 줘.
다운로드 상태 기계는 재사용하고 주소를 presentation/platform/release별로 분리해 줘.
2D 팩이나 다른 플랫폼/ABI의 팩은 적용 전에 거절해 줘.
기본 오프라인 완주용 LocalCore를 보존하고 원격 팩은 모델·재질·효과 등 시각 자산만 담아 줘.
실제 빌드의 셰이더·의존성·불필요한 2D 아틀라스 포함 여부를 검사해 줘.
테스트 업로드도 대상 경로와 비용을 먼저 확인하고 기존 릴리스를 덮어쓰지 마.
반복 로드/해제·취소·오프라인·롤백 검사를 기록해 줘.

적용할 세부 규칙:
경로 예시는 content/3d/android/release-001/과 content/3d/windows/release-001/이다. 2D 경로를 덮어쓰지 않는다. 릴리스 메타데이터에 presentation=3d, platform, contentAbi, 최소/최대 지원 앱 버전과 카탈로그 주소를 둔다.

VisualCatalog는 같은 itemId/enemyId를 3D 주소로 매핑한다. LocalCore 에는 기본 플레이어·적·보스·맵·효과가 모두 있다. 추가 팩은 외형을 제공하며 C# 코드나 새로운 저장 규칙을 원격으로 교체하지 않는다.

3D 셰이더와 재질이 개발용 Editor에서는 보이지만 빌드에서 누락될 수 있으므로 실제 번들을 사용한 Development/배포 빌드를 검사한다. 2D 전체 아틀라스가 필요 없이 3D 빌드에 포함되는지도 의존성 보고서에서 확인한다.

코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘. 수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.
