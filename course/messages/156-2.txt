내가 만든 하네스의 실제 경로와 현재 게임 후보를 확인하고 game-feature로 이 작업을 처리해 줘. 필요한 담당 역할만 고르고 구현·QA·독립 검토를 분리해 줘. 변경안·승인한 후보·Unity 통합·현재 소스 검사를 실제로 연결하고, 참고 완성본으로 우회하지 마.

대장간 기능 조합의 불변 조건 검사를 QA 역할로 작성해 줘.
ID 유일성·재료한도·룬호환·revision·run상태정리·보상1회·토큰반환·실제도달성을 확인해 줘.
100개 논리 시드와 실제 Unity 몸체 검사·실기기 검사 수를 분리해 줘.
실패 시드·버전·명령 시퀀스·소스 해시를 남기고 최초 반례를 보존한 채 최소화해 줘.
검사 순서를 바꿔도 전역상태 누수로 결과가 달라지지 않는지 확인해 줘.

이 기능의 규칙:
개별 기능의 PASS 를 더해도 조합 성공은 보장되지 않는다. 룬 장비를 창고에 넣고, 유물을 선택하고, 동료가 보스를 잡고, 앱을 다시 켰을 때 장비·룬·보상이 남는지 따로 본다. 동일 논리 조건의 대량 검사와 실제 화면·기기 검사를 섞어 한 개 수치로 숨기지 않는다.

핵심 불변 조건은 전체 아이템 ID 유일성, 재료 범위0~999, 슬롯 호환, 거래 revision 단조 증가, 유물의 run 범위, 죽은 적의 보상 한 번, 공격 토큰 누수 없음, 필수 방 도달성이다. 무작위 검사에는 seed·generatorVersion·입력·실패 단계·소스 해시를 남겨 재현 가능하게 한다.

실패 입력을 줄여 가장 작은 재현을 만들되 최초 실패 자료를 지우지 않는다. 100개 시드를 실행했다면 각 시드의 결과와 fallback 수를 기록한다. fallback을 사용한 시드를 정상 생성 성공에 포함하지 않는다. 테스트 순서에 따라 전역 난수나 static 상태가 새는 문제도 순서 변경 실행으로 확인한다.

코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘. 수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.
