내가 만든 하네스의 실제 경로와 현재 게임 후보를 확인하고 game-feature로 이 작업을 처리해 줘. 필요한 담당 역할만 고르고 구현·QA·독립 검토를 분리해 줘. 변경안·승인한 후보·Unity 통합·현재 소스 검사를 실제로 연결하고, 참고 완성본으로 우회하지 마.

기존 하네스의 실제 기능을 확장팩 격리 사본에서 장애 시험해 줘.
권한밖쓰기·read_files누락·review_fail·0개 NUnit·seal후변경·미확인비용을 분리해서 검사해 줘.
일부러 유료 호출을 낭비하거나 실제 Editor를 임의 종료하지 마.
기존 run 상태를 AI 편집하지 말고 recover/retry의 조건을 만족할 때만 사용해 줘.
계약이 바뀌면 새 run을 만들고 옛 성공 증거를 새 성공으로 복사하지 마.

이 기능의 규칙:
이 작업은 하네스 기능을 실제 확장 작업에 적용하는 훈련이다. 한 run에는 작은 기능 하나만 넣고, 의도적으로 입력 누락·구현자 테스트 쓰기·비평가 코드 쓰기·리뷰 실패·필수 NUnit0개·seal 후 소스 변경을 주입한다. 프로그램이 중단하는 것이 정상인 경우를 익힌다.

기본 하네스의 retry-task는 같은 계약의 제한된 재시도이며 새 계획을 만드는 도구가 아니다. code bug나 permission 설계 변경은 새 run이다. 오래된 RUNNING은 프로세스가 실제 종료됐는지 확인한 뒤 recover하고, 잠금 해제도 소유자 종료를 확인한 뒤 수행한다. 시간만 지났다는 이유로 다른 Editor를 종료하지 않는다.

비용은 예약·추정 청구·미확인 상태를 구분한다. 라이브 비용 메타데이터가 없으면 무한 재시도하지 않는다. 테스트용 예산 실패는 mock fixture와 로컬 테스트로 먼저 연습하고 고의로 실제 유료 호출을 소모하지 않는다. 성공한 예전 XML을 새 해시 후보에 쓰는 것도 실패로 남긴다.

코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘. 수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.
