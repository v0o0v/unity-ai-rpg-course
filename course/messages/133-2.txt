내가 만든 하네스의 실제 경로와 현재 게임 후보를 확인하고 game-feature로 이 작업을 처리해 줘. 필요한 담당 역할만 고르고 구현·QA·독립 검토를 분리해 줘. 변경안·승인한 후보·Unity 통합·현재 소스 검사를 실제로 연결하고, 참고 완성본으로 우회하지 마.

퀘스트 이름표가 필터에 숨겨지는 실패를 격리된 E01 테스트 후보에서 재현해 줘.
실패 테스트와 실제 소스 해시를 먼저 확보한 뒤 새 수정 run을 계획해 줘.
QA의 assertion을 약하게 만들거나 퀘스트 드롭을 제거하지 마.
필터 우선순위만 최소 수정하고 전체 보기·일반 장비·풀 재사용·모바일 입력 회귀를 다시 검사해 줘.
기존 run의 state/config/응답을 직접 고쳐 성공으로 만들지 마.
승격한 최종 2D 소스의 검사와 이전 후보 검사 결과를 구분해 줘.

이 기능의 규칙:
첫 기능은 하네스의 전체 흐름을 실제로 배울 기회다. 예를 들어 ‘희귀만 필터일 때 퀘스트 이름표도 숨김’이라는 오류를 격리 복사본에 넣는다. QA가 명세에서 테스트를 작성하고 실제로 실패하는 것을 먼저 확인한다. 새 수정 계획에는 그 실패 보고서와 코드 해시를 입력으로 제공한다.

stage 이후 동일 run의 proposal을 다시 실행하거나 state.json을 수정하지 않는다. 수정한 acceptance·코드는 새 revision/new run으로 만든다. 예산 부족·통신 중단과 코드 결함도 다르다. 같은 입력의 일시 실패만 제한된 retry-task 후보이며, 잘못된 코드는 원인을 바꾼 새 작업이다.

stage는 원본에 적용하지 않는다. 검증 후보를 다음 기준으로 승격하려면 검토된 diff와 .meta를 별도 Git 통합 브랜치에 적용하거나 후보를 새 개발 원본으로 명시한다. .git은 스냅샷에 복사되지 않으므로 후보에 원래 Git 이력이 있다고 가정하지 않는다. 승격 뒤 최종 소스에서 다시 검사한다.

코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘. 수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.
