내가 만든 하네스의 실제 경로와 현재 게임 후보를 확인하고 game-feature로 이 작업을 처리해 줘. 필요한 담당 역할만 고르고 구현·QA·독립 검토를 분리해 줘. 변경안·승인한 후보·Unity 통합·현재 소스 검사를 실제로 연결하고, 참고 완성본으로 우회하지 마.

대장간 기본 장비 레시피3개를 추가해 줘. 기존 아이템18종은 유지하고 신규 ID 만 사용해 줘.
미리보기에서는 ID 생성과 재료 차감·난수 사용을 하지 마.
성공 커밋 한 번에 재료 차감·아이템 추가·revision 증가·영수증을 저장해 줘.
동일 requestId는 동일 결과 ID를 돌려주고, payload가 바뀌면 거부해 줘.
가방이 가득 차면 거래 전체를 거부하고 재료를 유지해 줘.
기존 분해와 제작이 같은 거래 서비스의 규칙을 쓰게 해 줘.

이 기능의 규칙:
대장간 장비는 무기·갑옷·장신구 하나씩 세 개만 추가한다. 제작검은 고철6+불씨2, 제작갑옷은 고철8+불씨1, 제작장신구는 고철3+가루3을 소비한다. 초기 보너스는 각각 공격력4, 방어력3, 최대 마나5다. 기존 18종 아이템 정의를 바꾸지 않고 새 ID를 추가한다. 보너스가 기존 데이터의 어느 필드에 들어갈지는 실제 구조에 맞춰 확정한다.

첫 제작은 결과 능력치를 고정해 무작위 재추첨과 저장 악용을 줄인다. 미리보기는 결과 정의·재료 비용·남을 공간만 계산하며 instanceId나 RNG를 소비하지 않는다. 실제 커밋 때 새 instanceId를 한 번 생성하고 영수증에 저장한다. 같은 requestId에 다른 레시피를 넣으면 이전 결과로 성공시키지 말고 request payload 충돌로 거부한다.

가방이 가득 차면 재료가 충분해도 거래를 거부한다. 자동 바닥 드롭으로 바꾸지 않는다. 제작 성공은 재료 차감과 아이템 추가가 같은 상태에 들어간 때다. 버튼 애니메이션은 이 결과 이벤트를 구독한다.

이 세 제작 장비는 일반 등급·고정 보너스로 시작한다. 따라서 분해 보상은 일반 표를 사용하며 제작→분해가 재료 증가 순환이 되지 않는다. 제작 등급을 바꾸려면 레시피와 경제 검사를 함께 변경한다.

초기 제작 표는 forge_blade(무기, 공격+4): 고철6·불씨2, forge_vest(갑옷, 방어+3): 고철8·불씨1, forge_charm(장신구, 최대MP+5): 고철3·룬가루3이다. 모두 일반 등급이고 랜덤 옵션은 생성하지 않는다. 장신구의 최대 MP 보너스 경로를 기존 능력치 합산과 저장에 추가해 줘.

코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘. 수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.
