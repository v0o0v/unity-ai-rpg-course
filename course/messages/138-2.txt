내가 만든 하네스의 실제 경로와 현재 게임 후보를 확인하고 game-feature로 이 작업을 처리해 줘. 필요한 담당 역할만 고르고 구현·QA·독립 검토를 분리해 줘. 변경안·승인한 후보·Unity 통합·현재 소스 검사를 실제로 연결하고, 참고 완성본으로 우회하지 마.

장비 분해와 세 재료 지갑을 기존 저장·인벤토리에 추가해 줘.
분해 금지 조건과 보상 표를 이번 명세대로 사용하고 무작위 재료를 새로 추첨하지 마.
requestId·expectedInventoryRevision·instanceId를 검증하는 거래 경로를 만들어 줘.
삭제·보상·revision·처리 영수증이 같은 새 저장 상태에 들어가게 하고 저장 실패 시 전부 원복해 줘.
schema2→3 이전은 사본으로 검증하고 기존 ID·옵션·골드·퀘스트·스킬을 보존해 줘.
UI 확인창만으로 중복 방지를 했다고 보고하지 마.

이 기능의 규칙:
재료는 장비 24칸을 차지하지 않는 별도 지갑으로 관리한다. 고철·불씨·룬 가루의 세 종류, 종류별 최대 999다. 분해 시 일반 장비는 고철2, 마법은 고철3+가루1, 희귀는 고철4+가루2+불씨1을 주는 초기 표를 사용한다. 장착·즐겨찾기·퀘스트·룬 삽입 장비는 분해할 수 없다.

UI 버튼을 비활성화하는 것만으로 중복 분해를 막을 수 없다. requestId, 기대 inventoryRevision, 아이템 instanceId를 가진 명령을 거래 서비스에 전달한다. 사전 검증과 결과 계산은 복사 상태에서 수행하고, 저장 가능한 완전한 새 상태를 만든 뒤 한 번에 교체한다. 쓰기 실패 시 기존 아이템과 재료를 유지한다.

schema3는 기존 schema2 필드를 유지하고 materialWallet·stash·favoriteIds·socketData·questFlags의 명시적 기본값을 추가한다. 새 원본 저장을 바로 덮어쓰지 않고 사본에서 검사한다. 게임 중 모든 거래 때 저장 여부를 결정한 뒤 프로젝트 전체에서 같은 방식을 유지한다. 본 확장은 마을 영구 거래를 성공 시 내구 저장하는 방식으로 고정한다.

코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘. 수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.
