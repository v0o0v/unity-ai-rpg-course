내가 만든 하네스의 실제 경로와 현재 게임 후보를 확인하고 game-feature로 이 작업을 처리해 줘. 필요한 담당 역할만 고르고 구현·QA·독립 검토를 분리해 줘. 변경안·승인한 후보·Unity 통합·현재 소스 검사를 실제로 연결하고, 참고 완성본으로 우회하지 마.

대장간의 선택 고해상도 2D 팩을 기존 Addressables 흐름에 연결해 줘.
새 전투·저장 코드는 앱에 포함하고 원격팩은 외형만 바꾸도록 해 줘.
팩 mode·contentContract·기본 fallback을 확인하고 미호환 팩을 거부해 줘.
취소 후 늦은 콜백·0바이트 캐시·실제 load실패·오프라인을 따로 검사해 줘.
빌드 준비·외부 업로드·기기 다운로드 성공을 구분하고 승인 없이 업로드하지 마.

이 기능의 규칙:
기본 대장간 지역·보스·룬·동료의 규칙과 저해상도 외형은 앱에 포함한다. 선택 고해상도 팩은 스프라이트·타일·효과·소리만 교체한다. C# 코드를 Addressables 데이터로 받아 실행하거나 원격 팩이 없으면 필수 퀘스트를 막는 구조는 만들지 않는다.

팩 manifest는 mode=2D, contentVersion, minimumAppContentContract, 아틀라스·셰이더 필요 조건을 기록한다. 앱의 코드 계약과 호환되지 않으면 받지 않고 기본 외형을 유지한다. Addressables 업데이트는 이전 content state 보존과 빌드 그룹 설정에 의존하므로 이전 빌드 상태 파일을 삭제하지 않는다. 

다운로드0바이트는 캐시가 있다는 뜻일 수 있으며 프리팹 로드 성공과 다르다. 취소한 요청의 늦은 완료 콜백이 새 화면을 덮지 않도록 request generation과 소유자를 확인한다. 선택한 외형이 바뀌어도 체력·몸체·사거리·저장 ID는 같아야 한다. 실제 업로드는 별도 승인하고, 로컬 준비물을 만들었다는 이유로 CDN 배포 성공이라 하지 않는다.

코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘. 수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.
