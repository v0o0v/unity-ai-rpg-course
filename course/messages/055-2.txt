현재 프로젝트의 실제 파일과 이미 결정한 규칙을 먼저 확인해 줘. 이름이 다른 기존 구현이 있으면 새로 중복 제작하지 말고 그 구현에 연결해 줘.

ART_BIBLE과 ArtLab2D를 현재 게임 기준으로 정리해 줘.
ActorRoot의 XY 좌표, Physics2D, 몸체 반경, 피해 권한, A*는 그대로 두고 VisualRoot의 Sprite만 교체해 줘.
캐릭터 64×64, PPU 32, 네 방향, 발 pivot과 타일 64×64, PPU 64를 기준으로 실제 화면 높이를 확인해 줘.
처음에는 S 방향 walk 6프레임과 attack 6프레임만 검수하고, 승인 전에 전체를 유료 생성하지 마.
각 프레임의 alpha, 발 기준점, 크기, 오른손 무기, 정렬을 실제 파일로 확인해 줘.
Sprite를 보기 위해 NavMeshAgent나 3D 바닥을 추가하지 마.
서비스 선택, 권한, 비용 한도, 출처, 실제 파일 경로와 미검증 항목을 기록해 줘.

적용할 세부 규칙:
• 항목: 시점 / 기본 규격: 고정 2D 탑다운. 몸의 앞과 옆이 보이는 쿼터뷰풍 그림
• 항목: 캐릭터 캔버스 / 기본 규격: 64×64 RGBA. 프레임별 임의 크롭 금지
• 항목: 게임 PPU / 기본 규격: 캐릭터 32, 타일 64. 실제 화면 높이로 최종 확인
• 항목: 방향 / 기본 규격: S/W/N/E = 화면 아래/왼쪽/위/오른쪽
• 항목: 프레임 목표 / 기본 규격: 방향별 idle 4, walk 6, attack 6, hurt 2, death 6. 네 방향 총 96프레임
• 항목: 최초 검수 / 기본 규격: 남쪽 walk 6프레임과 attack 6프레임만 먼저
• 항목: 발 기준 / 기본 규격: PNG 왼쪽 위 기준 (32,56) → Unity 정규화 pivot (0.5,0.125)
• 항목: 바닥 / 기본 규격: 64×64 정사각형, PPU 64, 일관된 이음새

128×128로 받았다면 게임 속 크기를 유지하도록 캐릭터 PPU를 64로 비례 조정한다. 프레임마다 불투명 범위에 맞춰 scale을 바꾸지 않는다. 그림의 검이 길어져도 몸체 반경 0.35와 기본 사거리 1.8은 바꾸지 않는다.

원본은 ArtSources/Raw, 정리본은 Clean, 패킹 결과는 Packed에 보존한다. 채택본만 Assets/_Game/Art로 들인다. API 키·계정 토큰·개인 사진을 원본 관리 폴더에 섞지 않는다. 참조 이미지의 사용 권한도 확인한다.

코드·설정·파일 생성·실행은 네가 맡고, 필요한 화면과 결과를 보여 줘. 수행하지 못한 작업과 필요한 승인·도구 연결은 구분해서 알려 줘.
