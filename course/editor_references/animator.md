# Animator — 상태와 전환이 동작을 연결하는 방식

사각형은 동작 상태, 연결선은 상태 사이의 전환을 보여 줍니다. 흐름도처럼 생겼지만 이번 그림은 퀘스트가 아니라 캐릭터 애니메이션 제어입니다.

**공식 문서 기준:** Unity Manual 6.3. 공식 문서에 남아 있는 이전 UI 예시입니다. 현재 창의 색·상태 표시와 다를 수 있으며 캡처 빌드는 미표기입니다.

## 화면 읽기

### 1. 왼쪽 · Parameters

Forward·Strafe·Fire·Die 같은 입력 값이 보입니다. 게임 코드가 보내는 값과 전환 조건이 실제로 연결되어야 합니다.

### 2. 가운데 · 상태

Grounded·Jumping·Falling 등의 상태가 표시됩니다. 예시의 상태 이름을 그대로 복제할 필요는 없습니다.

### 3. 상태 사이의 화살표

어느 상태로 이동할 수 있는지 보여 줍니다. 실제 조건·시간·우선순위는 해당 전환의 Inspector와 플레이 결과로 확인합니다.

## 잠깐 확인하기

공격 상태로 들어가면 자동으로 피해가 적용될까요? 아닙니다. 시각 동작과 전투 판정을 연결해야 하며, 애니메이션과 타이머가 피해를 두 번 적용하지 않는지 따로 검사합니다.

## 이 화면이 증명하지 않는 것

정지 이미지는 실제 전환이나 공격 타이밍을 증명하지 않습니다. AI가 현재 캐릭터의 Animator와 실제 게임 동작을 함께 확인하게 합니다.

## 내 프로젝트의 실제 창 확인 요청

공식 예시와 실제 프로젝트가 같은지, 캡처 기능이 연결되어 있는지 확인하기 위한 추가 요청입니다. 구현·설정 변경은 자동 승인하지 않습니다.

```text
현재 캐릭터에 연결된 Animator Controller를 열어 실제 파라미터·상태·전환과 애니메이션 클립을 설명해 줘. 이동과 공격 로직이 어떤 값을 보내는지 추적하고 시각 동작과 피해 처리의 연결을 구분해 줘. 참고 그림의 상태 이름을 그대로 만들지 말고 현재 프로젝트를 확인해 줘. 재생이나 전환 검사는 현재 작업을 방해하지 않는 시작 상태를 준비한 뒤 진행해 줘.
화면을 보여 줄 수 있는 도구가 있다면 실제 창을 캡처해 새 파일로 남기고 파일 경로·프로젝트·버전·현재 상태를 함께 알려 줘. 민감정보가 보이면 먼저 안전한 화면으로 준비해 줘. 캡처 도구가 없으면 연결이 없다고 설명하고 AI가 그린 가짜 Editor 화면으로 대신하지 마. 코드를 직접 입력하도록 요구하지 마.
```

기존 실습과 필수 검사는 유지합니다. 창 캡처가 없으면 없다고 기록하고 다른 그림으로 실행 결과를 만들어 채우지 않습니다.
