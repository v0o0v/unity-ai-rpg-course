# Console — 오류 줄과 상세 원인을 함께 읽기

오류가 있다는 색만 보지 않고, 어떤 파일에서 무슨 문제가 보고되었는지 읽는 예시입니다. 화면의 CS0103은 공식 샘플에 있는 오류이며 내 프로젝트 오류가 아닙니다.

**공식 문서 기준:** Unity Manual 6.3. 문서 기준은 6.3이며 원본 캡처의 정확한 Editor 빌드는 표시되지 않았습니다.

![Unity 공식 문서의 실제 UI 예시 — 내 프로젝트 실행 결과 아님](https://docs.unity3d.com/6000.3/Documentation/uploads/Main/Console.png)

**출처:** [Unity Technologies · Unity Documentation](https://docs.unity3d.com/6000.3/Documentation/Manual/Console.html) · [원본 이미지](https://docs.unity3d.com/6000.3/Documentation/uploads/Main/Console.png) · [이용 조건](https://unity.com/legal/docs-terms). 원본 수정 없음. 사진은 온라인에서 읽습니다.

## 화면 읽기

### 1. A · 도구 막대와 필터

Clear·Collapse와 로그 종류 필터가 보입니다. 기록을 지우거나 필터로 숨기면 오류가 없어진 것처럼 보일 수 있으므로 현재 설정도 확인합니다.

### 2. C · 메시지 목록

파일 경로와 줄 번호, 오류 종류가 함께 표시됩니다. 마지막 메시지만 보고 추측하기보다 실제 오류 순서와 재현을 AI가 조사하게 합니다.

### 3. D · 상세 영역

선택한 메시지의 내용을 읽는 곳입니다. 짧은 캡처만 보내지 말고 AI가 원본 로그와 관련 소스를 읽도록 요청합니다.

## 잠깐 확인하기

Console이 비어 있으면 곧바로 성공일까요? 아니요. 필터·기록 삭제 여부와 실제 실행한 검사, 현재 소스가 같은지 확인해야 합니다.

## 이 화면이 증명하지 않는 것

Console 캡처는 자동 테스트 결과나 휴대폰 조작 검사를 대신하지 않습니다. 이 예시의 Clear 동작을 수강생이 따라 누를 필요는 없습니다.

## 내 프로젝트의 실제 창 확인 요청

공식 예시와 실제 프로젝트가 같은지, 캡처 기능이 연결되어 있는지 확인하기 위한 추가 요청입니다. 구현·설정 변경은 자동 승인하지 않습니다.

```text
현재 프로젝트의 Console과 원본 로그를 읽기 전용으로 확인해 줘. 오류·경고 필터와 Play 여부를 먼저 기록하고, 실제 오류가 있으면 첫 관련 오류의 경로·줄·상세 내용과 재현을 보여 줘. 오류가 없다면 임의 오류를 만들어 캡처하지 마. Clear로 기록을 지우지 말고 테스트 결과와 Console 상태를 구분해 줘.
화면을 보여 줄 수 있는 도구가 있다면 실제 창을 캡처해 새 파일로 남기고 파일 경로·프로젝트·버전·현재 상태를 함께 알려 줘. 민감정보가 보이면 먼저 안전한 화면으로 준비해 줘. 캡처 도구가 없으면 연결이 없다고 설명하고 AI가 그린 가짜 Editor 화면으로 대신하지 마. 코드를 직접 입력하도록 요구하지 마.
```

기존 실습과 필수 검사는 유지합니다. 창 캡처가 없으면 없다고 기록하고 다른 그림으로 실행 결과를 만들어 채우지 않습니다.
