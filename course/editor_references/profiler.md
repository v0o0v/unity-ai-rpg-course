# Profiler — 측정 대상·느린 프레임·세부 구간 읽기

막대와 선의 색보다 먼저 무엇을 측정했는지 읽습니다. 그다음 오래 걸린 프레임을 선택하고 아래 타임라인에서 해당 프레임의 구간을 따라갑니다.

**공식 문서 기준:** Unity Manual 6.0. 6.0 문서의 공식 예시이며 이 과정의 6.3 또는 특정 Android 기기의 실제 측정이 아닙니다. 정확한 캡처 빌드는 미표기입니다.

## 화면 읽기

### 1. 위쪽 · 대상과 기록 컨트롤

Editor·Play Mode·연결 기기 중 어디의 기록인지 확인합니다. Editor 데이터로 휴대폰 성능을 대신 판정하지 않습니다.

### 2. 가운데 · 시간 변화

튀어 오른 프레임을 고르고 같은 재현 조건을 기록합니다. 이 그림의 수치를 내 게임 성능으로 사용하지 않습니다.

### 3. 아래 · Timeline

Main Thread와 Render Thread 등의 시간을 나누어 봅니다. GC.Alloc 표시는 할당 관련 표본이며, 이 화면만으로 모든 메모리 누수를 판정하지 않습니다.

## 잠깐 확인하기

수정 후 평균 FPS가 올랐으면 끝일까요? 같은 기기·빌드·장면·입력으로 프레임 시간과 긴 끊김을 다시 비교하고 기능이나 가독성이 훼손되지 않았는지도 봅니다.

## 이 화면이 증명하지 않는 것

이 사진은 Memory Profiler 스냅샷 창이 아닙니다. 메모리 잔류·할당·GPU·발열은 각각 필요한 도구와 실기기 측정으로 확인합니다.

## 내 프로젝트의 실제 창 확인 요청

공식 예시와 실제 프로젝트가 같은지, 캡처 기능이 연결되어 있는지 확인하기 위한 추가 요청입니다. 구현·설정 변경은 자동 승인하지 않습니다.

```text
현재 프로젝트의 실제 Profiler 대상과 기록 유무를 먼저 확인해 줘. 이미 측정한 결과가 있으면 기기·빌드·품질·재현 조건과 선택 프레임의 Timeline을 보여 줘. 기록이 없으면 수치를 만들어 내지 말고 같은 상황을 반복할 측정 절차를 준비해 줘. Editor 결과를 Android 성능으로 표시하지 말고, 메모리 스냅샷과 프레임 기록도 구분해 줘.
화면을 보여 줄 수 있는 도구가 있다면 실제 창을 캡처해 새 파일로 남기고 파일 경로·프로젝트·버전·현재 상태를 함께 알려 줘. 민감정보가 보이면 먼저 안전한 화면으로 준비해 줘. 캡처 도구가 없으면 연결이 없다고 설명하고 AI가 그린 가짜 Editor 화면으로 대신하지 마. 코드를 직접 입력하도록 요구하지 마.
```

기존 실습과 필수 검사는 유지합니다. 창 캡처가 없으면 없다고 기록하고 다른 그림으로 실행 결과를 만들어 채우지 않습니다.
