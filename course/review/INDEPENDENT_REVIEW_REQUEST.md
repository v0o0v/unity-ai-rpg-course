# 독립 비평가 재심 계약 — 아직 실행되지 않음

이 파일은 다음에 실제 독립 worker를 실행할 때 전달할 입력입니다. 자체 검토 보고서를 독립 심사 결과로 복사하지 마세요.

검토 대상: 이 ZIP의 index.html, data/lessons.json, data/prompt_guides_v13.json, pages/, WORK_SKILLS/, AI_REFERENCE/, review/issue_ledger.json. 원본 v12의 기록은 review/prompt_changes.json과 review/sentence_repairs.json에 있습니다. 실제 컴퓨터에서 해제한 경로를 확인하고 다른 프로젝트를 수정하지 않습니다.

목표: Unity 기본 실습 경험자가 개발 코드·명령·설정을 직접 작성하지 않고, 자연어 AI 요청·승인·직접 플레이로 게임·하네스·Editor 도구를 만들고 독립적인 새 기능까지 추가할 수 있는가?

정독을 분담할 경우 서로 다른 별도 worker를 사용하며 하위 위임하지 않습니다. ①학생 흐름·설명/선행 관계 ②Unity·AI·하네스 실제 실행 계약 ③현재 HTML의 PC/모바일·라이트/다크 시각 검토를 분리합니다. 가능한 수만 쓰고, 수행하지 못한 범위는 미검증으로 남깁니다.

1. 먼저 원래 요구와 현재 교재를 직접 읽고, 읽은 범위·열어 본 화면을 기록합니다. 작성자의 수정 설명으로 판단을 대신하지 않습니다.
2. C01~C20 수정 여부를 같은 반례로 대조하고 새로운 문제를 찾습니다. UI 자동 검사와 실제 교육 효과는 구분합니다.
3. ‘현재 학생은 무엇을 어디에 보내고, 무엇을 보면 다음 단계로 가는가’를 각 관문에서 추적합니다. 이미 있어야 한다고 가정한 역할·파일·키·장면·UI가 실제 이전 과정에서 만들어지는지 검사합니다.
4. AI 프롬프트에 숨겨진 교재 번호·존재하지 않는 고정 파일·수동 코딩 요구가 있는지 찾습니다. 초기 로그인/승인/기기 연결/플레이는 명시적 사람 역할입니다.
5. 문장 이유가 해당 요구를 설명하는지, 근거 없는 추측이나 단어 연상만으로 다른 기술을 설명하지 않는지 검사합니다.
6. 수정 권한 없이 독립 결과를 review/independent/의 새 파일로 제출합니다. 형식: 범위, PASS/FAIL/BLOCKED, 근거 위치, 재현, 영향, 최소 수정, 미확인.
7. 수정 후에는 새 manifest와 HTML 해시를 받아 재심합니다. 기존 결과를 새 파일의 성공으로 재사용하지 않습니다.

금지: 점수 맞추기, 노력·수정량으로 통과, 실제 없는 Unity/폰/모델 호출 주장, Python 테스트를 게임 완주로 표현, 직접 작업물을 바꾼 뒤 독립 검토였다고 표현.

최종 판정: 문서·도구의 별도 판정과 실환경·초보자 능력 검증을 분리합니다. 실환경 자료가 없으면 출시에 충분한 과정이라는 전체 목표는 보류합니다.
