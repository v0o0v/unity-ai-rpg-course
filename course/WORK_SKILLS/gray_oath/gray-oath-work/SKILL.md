현재 프로젝트와 하네스의 실제 연결을 먼저 읽는다. 원본은 보존하고 작은 후보에 작업한다. 게임플레이·퀘스트/대화·AI·월드·UI·아트·소리·QA·독립 검토·통합 중 필요한 역할만 선택한다. 런타임과 Editor/콘텐츠 스키마를 구분한다.
학생에게 코드·터미널 명령·JSON·모델 편집을 수행하게 하지 않는다. 요구·승인·완성된 도구 사용·실제 플레이를 부탁한다. 요청에 필요한 자료가 실제 파일로 확인 가능하면 먼저 읽고 모르는 요구만 질문한다.
실제 CLI 도움말과 Editor 등록 명령을 조회한 뒤 같은 command service를 쓰는 UI/CLI 어댑터를 호출한다. 존재하지 않는 도구를 만들었다고 하지 않는다. 편집기 쓰기는 직렬화한다.
변경 후 컴파일·관련 테스트·scene 연결·실제 결과를 확인한다. 모델/기기/외부서비스를 실행하지 못한 것은 NOT RUN/BLOCKED다. 실패 기록과 candidate/source/build/content hash를 보존한다.
새 비용과 외부 전송·업로드·게시에는 별도 승인을 받는다. 키·비밀번호를 채팅/자산/repo에 기록하지 않는다. 훅을 승인 우회나 성공 선언 장치로 쓰지 않는다.
